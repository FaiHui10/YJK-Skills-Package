# 真实工程（模式 B）—— 写入路径、限制与证据

真实工程（已有 YJK 工程、已有设计结果）的难点不在选型，而在"**把新截面写回模型并让 YJK 认**"。
本文固化这条路线上必须遵守的约定与判据。

> **本文只讲"写回模型"这一侧。** 启动 YJK、IPC 通道、Config.ini、单实例、命令链
> 这些**驱动侧**内容在 **`yjk-auto-drive` 技能**里（含它的
> `references/setup-checklist.md` 与 `references/troubleshooting.md`）。

---

## 一、先搞清楚：哪个文件才是模型

| 文件 | 作用 | 能否外部改 |
|---|---|---|
| `<工程名>.yjk` | **建模模型**（图形+建模数据），YJK 打开工程时读它 | 二进制，改不了 |
| `<工程名>.ymd` | **模型库/计算模型**（SQLite，77 张表：柱段/截面/层/荷载…） | 能改，但见下 |
| `设计结果\wpj*.out` | 每根柱的设计结果（截面、短柱标记、Uc、Nu、配筋） | 只读，是最可靠的"真值来源" |

要点：

1. **不要写死模型库文件名**。它通常是 `<工程名>.ymd`，但并非绝对。
   驱动技能的 `scripts/env.py` 能自动识别（扫目录里所有 `*.ymd`，挑含 `tblColSect` 的那个）：
   ```powershell
   & $py -X utf8 -B "<yjk-auto-drive>\scripts\env.py" --proj-dir "<工程目录>"
   ```
2. **直接改现有工程目录里的 `.ymd` 不推荐**（YJK 打开工程时会按需要重写它）。
   正确的做法是：写好一份 ydb → 用 `UINew` 新建工程 → `yjk_importydb` 导入
   （见第三节路径 2），或直接在界面里改（路径 1）。
3. **建模端显示与计算端取值是两件事**。判定"改没改成功"要以**计算输出**
   （`wpj*.out` 的 `Rcc=`/`Uc`）为准，不要以建模界面显示为准。
4. **逐自然层混凝土等级在模型库里、可以程序化读写**，有效字段是
   **`tblStdFlr.Para` 下标 2/4/5/6**（板/柱/梁/墙 强度×10），详见第二节。

## 二、逐层混凝土等级在哪里（可程序化读写）

**结论：等级写在模型库里、而且写了就生效。不需要动 `.yjk`。**

- **有效字段：`tblStdFlr.Para` 串里 idx2/4/5/6 = 板/柱/梁/墙 强度×10**（`300` = C30，`600` = C60）。
  即等级是**"标准层"层面的参数**；`tblStdFlrPara(StdFlrID,Kind,ParaVal)` 是它的展开表。
- **反例（关键）**：`tblProperty` 里 `Name='HNTDJ'`（ShapeVal = -等级）的行使**每构件一条**，
  **只改它不生效** —— 其余不动、只改 HNTDJ 时 YJK 仍按原等级计算。
- 稳妥做法：**`tblStdFlr.Para` + `tblStdFlrPara` + `tblProperty.HNTDJ` 三者一起写**
  （`scripts/write_sections.py` 已内置；给了 `--grades`/`--grades-file` 就会写）。
- 外部生成的模型可能**没有 HNTDJ 行**，此时改写 0 行属正常，不是失败。
- `.yjk`（YJKG）仍是二进制、外部读写不了，但**它不独占等级信息**，
  所以"必须在界面里逐层设等级"这个限制不存在。

### 校验等级有没有写进去：反算实际强度

由 `fc = Nu × 1000 / (b × h × Uc)` 反算实际 `fc`，与真值等级比对：

- 若 `Uc实算 / Uc真值 ≈ 强度比`（例如 27.5/14.3 ≈ 1.92，正是 C30→C60 的比值），
  说明**等级没写进去**，YJK 仍按原等级算。
- 写对了则 `wpj*.out` 的 `Rcc=` 与 `Uc` 会同步变化，且 `Uc实算 ≈ Uc真值`。

这条反算对**任何**"改了没生效"的怀疑都适用，是本路线最省事的一道闸。

### 拆分标准层 + 导入（逐层不同截面/等级的前置）

要做"逐层不同截面/等级"，得先把**一个标准层 + N 个自然层**拆成**N 个标准层**
（`split_stdflr.py`）。这条路可行，但有三个必须满足的前提，否则导入会**静默塌陷**：

| 前提 | 不满足的后果 |
|---|---|
| 几何行的**行内引用**按「本次复制」重映射（键 = (源标准层ID, 覆盖的自然层元组)） | 只有**首尾**标准层留住几何，中间全空 |
| **不删除原标准层**（每个源标准层的第一个自然层留在原标准层上） | `tblFloor=0`，自然层全丢，柱梁板几何归零 |
| 新标准层的 `ID`/`idNew` 取**最小可用**且**早于自然层** | 自然层被整批丢弃 → `tblFloor=0`；或几何全塌到最后一个标准层 |

详细约定与症状对照见 SKILL.md「逐层标准层拆分」与「算不通的症状对照表」。

**导入后必须逐表核对**（见第四节），确认标准层数、自然层数、节点/梁/柱/板行数
与拆分模型一致，再做全量计算。

## 三、三条写入路径（按推荐度排序）

### 路径 1（推荐，零风险）：在 YJK 界面里「替换截面」

- 选某标准层的某组柱 → 替换截面 → 给目标尺寸；可批量选柱，逐标准层逐组做。
- 材料/荷载/梁板墙/标准层**一律不动**，成果直接落在原工程；不存在兼容性问题。
- 之后点「生成数据 + 全部计算」，由脚本做**只读复核**。

### 路径 2（`UINew` + `yjk_importydb`，推荐）

```
write_sections.py <src.ydb> <dst.ydb> --grades "…" --sections 优化截面清单.json
yjk_save → UINew <新工程>.yjk → yjk_importydb <dst.ydb>
        → yjk_repair → yjk_formnode 2 → yjk_formslab_alllayer → yjk_save
        → yjk_setlayersupport → yjkspre_genmodrel → yjk_transload_tlplan/tlvert
        → SetCurrentLabel IDSPRE_ROOT → yjkdesign_dsncalculating_all
        → SetCurrentLabel IDDSN_DSP
```

- 适用：**同结构下的"截面 + 逐层等级"替换**。
- 等级跟着 `tblStdFlr.Para` 走，库里写对了导入后就算对，**不需要** `.yjk` 提供材料信息。
- **两个必须同时满足的前提（否则静默失败）**：
  1. 等级写在 `tblStdFlr.Para[2,4,5,6]`（不是只写 `tblProperty.HNTDJ`）；
  2. 截面同时写 `tblColSeg.SectID` **和** `tblColSeg.idNewDef`。
     只写 `SectID` → 导入后柱段**全部回退到原截面**，且**无任何报错**。
- 这是目前唯一能"全自动批量改截面+改等级并实算复核"的路径，作为**方案比选/复核**工具；
  最终交付前建议再用路径 1 在界面上核对一次。

### 路径 2 的失败模式速查

| 症状 | 根因 |
|---|---|
| 导入成功、无报错，但截面全部回退 | 只写了 `SectID`，没写 `idNewDef` |
| 截面映射错乱、张冠李戴 | 新造的 `tblColSect.idNew` 有重复值（撞号） |
| 某组柱的截面变成别的组 | `ShapeVal` 串没按 `"1,<b>,<h>,6,<ID>,"` 规范写 / `Name` 非空 |
| Uc 假性超限（比预期大 ~1.9 倍） | 等级没写进 `tblStdFlr.Para`，YJK 按原等级算 |
| 标准层/自然层/构件数变了 | 动了结构（增删/重排标准层），见第二节 |

### 路径 3（官方 API 局部更新）

官方《建模接口说明》文档（随 YJK 安装包提供，路径以你的安装目录为准）里存在：

| 接口 | 作用 |
|---|---|
| `Hi_AddToAndReadYjk.ReadFromYJK()` / `ReadYdb()` | 读当前模型 / 读 ydb 成建模数据对象 |
| `Hi_UpdateInfo.ModifyObj(obj)` / `AddObj(obj)` | 局部更新里"改/增哪些对象" |
| `Hi_AddToAndReadYjk.ReflecToYJK(updateInfo)` | **把局部更新打到当前打开的模型上**（不动其它数据） |
| `CsToYjk.CreateYDB(path, name)` | 由建模数据生成 ydb |
| `DataFunc.ColSect_Def(mat, kind, ShapeVal, name)` | 建柱截面定义 |

这套接口的可用性取决于**官方建模接口与运行环境是否匹配**；未打通时走路径 2。
（接口名与调用方式以随安装包提供的《建模接口说明》为准。）

## 四、真实工程的操作顺序

### 全自动（路径 2）

```
1) 环境自检                    驱动技能的 `yjk_probe.py`（缺什么会直接告诉你）
2) 读取现状：解析 设计结果\wpj*.out  → 每根柱的 截面 / 短柱标记 / Uc / Nu / 材料
   （材料也可从 wmass.out 交叉核对；等级按自然层）
3) 选截面：按限值（短柱 / 非短柱 各取各的限值）×0.95 目标，逐 (标准层, 柱位组) 求最小截面
   —— 约束：50mm 模数、最小边长、保持矩形方向、竖向不出现下小上大
4) write_sections.py 写等级+截面 → colopt.py drive（= yjk_auto.py host --prep --calc）
5) verify_results.py 复核：轴压比超限=0、Uc ≤ 限值、位移角 ≤ 1/800、刚度比、配筋率超限
   —— 不满足则回到 3)，用新的真实轴力再选一轮（一般 1~2 轮收敛；
      某组持续超限时用 make_spec.py --keep <组> 把它排除在折减外）
```

**迭代对照表模板**（每轮单独一行，不要把不同轮次混成一个数字）：

| 方案 | 轴压比超限行 | 配筋率超限行 | 结论 |
|---|---|---|---|
| 原工程 | ? | ? | 作为基线，先确认等级写对（否则会出现假性超限） |
| 基准截面 + 真等级 | 应为 0 | ? | 等级写对后轴压比应全过 |
| 迭代 1（各组均折减） | ? | ? | 若有某组 Uc 超限，把它排除在折减外 |
| 迭代 N（最终） | **0** | ? | **推荐**；给出最不利 Uc 与限值 |

**复核要点**：

- 位移角要远小于限值；**刚度比（Ratx1/Raty1）与未改动的基线逐位比对** ——
  若与基线一致，属既有问题、非优化引起。
- 残余的**配筋率超限**要逐条归因：确认它在**原模型**与**未改动基线**上是否同样存在。
  若同样存在，属**既有问题**，需单独加大该柱或调整配筋，不算优化引入。

### 半自动（路径 1，零风险）

第 4) 步改成人手在界面「替换截面」→「生成数据+全部计算」，其余同。

## 五、判据与快速核对

**首选：一把梭 `scripts/verify_results.py`**

```powershell
& $py -X utf8 -B "<skill>\scripts\verify_results.py" "<工程目录>\设计结果" --db "<工程目录>\<模型>.ymd" --json verify.json
```

一次输出：逐(标准层×柱组) 轴压比是否满足 / 轴压比超限行数 / 位移角 / 刚度比 /
最大配筋率超限条数。**它内建了三个解析坑的处理**：

- `wdisp.out` 是 **`1/N` 分数**，且 **`1/9999` 是"≈0"哨兵，必须剔除**（否则会被读成最不利）。
  **全都是哨兵**时它是"位移远小于限值 → 满足"（实测位移 0.2mm/层高 3600mm），
  **不是"没核"**；脚本会用同文件 `h`/`Max-D` 列现算交叉印证，结果见 JSON 的
  `位移角哨兵交叉印证`。只有「未解析到 / 无文件」才算没核（rc=3）。
- `wmass.out` 的 `Ratx1/Raty1` 判据是 **`≥1.0` 满足**，不是"越大越好"。
- `wpj*.out` 配筋率超限用 `r"\*\*([^\r\n]*?配筋率[^\r\n]*?)([\d.]+)%>([\d.]+)%"` 抓。

**逐柱 Uc / 短柱 / 截面**（取每 (标准层,柱号) 的 Uc 最大者）：

```powershell
& $py -X utf8 -B -c "import sys;sys.path.insert(0,r'<本技能>\scripts');import verify_results as V;rows=[];[rows.extend(V.parse_wpj(p)) for p in __import__('glob').glob(r'<工程>\设计结果\wpj*.out')];w=V.worst_by_std_col(rows);[print(k, v['截面'], '短柱' if v['短柱'] else '', v['Uc'], v['材料']) for k,v in sorted(w.items())]"
```

- `verify_results.parse_wpj` 已能给出 `截面 / λc / 材料 / Nu / Uc / 超限`；
  **短柱标记**在构件行正文里（`砼柱 C60 短柱 矩形`），用 `"短柱" in 行文本` 判断。
- 位移角：`设计结果\wdisp.out` 里的"X/Y向最大层间位移角"（`1/N` 分数）。

## 六、模型库外部写入的硬性规则（若确实要写库）

1. **本工程正被 YJK 打开时不要写库**。写盘前先用驱动技能的 `env.py` 看
   「本工程是否正被打开」，为「是」就停手。
2. 实体 `ID` 必须 **< 100000**（`tblProjectPara.ID=100000` 是哨兵）；`idNew` 避开 `4294967295`。
   写前跑 `scripts/ydb_lint.py`。
3. 新增截面走 `write_sections.py` 的 `apply_to_db` 即可（`SectID` 精确到"标准层×柱号"）；
   **但必须同时写 `idNewDef`**，否则 `yjk_importydb` 静默忽略（见 SKILL.md「写回模型的关键点」）。
   截面行 `ShapeVal` 对矩形柱必须按 `"1,<b>,<h>,6,<ID>,"` 写，
   不能沿用"把 b,h 都写成 b"的方形写法。
4. **新号必须取全模型 `max(idNew)+1` 起**（跨表唯一），不要只按本表 `max+1` ——
   撞号会让 YJK 按 `idNew` 去重，导致柱段被静默丢弃。`write_sections.py` 的
   `check_idnew_global()` 已内置这道自检。
5. 写盘不等于生效：还要 `UINew`+`yjk_importydb`（路径 2）或界面改写（路径 1）。
