# 方法：为什么"少迭代"也能给出最优

## 问题

变量是「每层 × 每柱位分组」的柱截面边长（设为 50mm 步长）＋「每层」的混凝土等级。
10 层 × 3 组 + 10 个等级 = **40 个变量**，但实际只跑了 **3 轮**就收敛。原因不是走了捷径，
而是把"搜索"换成了"闭式求解 + 小枚举 + 不动点验证"。

## 为什么可以分解

选型的硬约束只有一个，而且它是**逐柱局部的**：

```
轴压比   Uc = N / (A · fc) ≤ [Uc]
```

对单根柱，N 已知时最小可行边长有闭式解：

```
A ≥ N / ([Uc] · fc)        →   side ≥ √(N / ([Uc] · fc))
```

于是求解分成两层，**都不需要搜索**：

| 维度 | 候选 | 求解方式 |
|---|---|---|
| 单组截面（等级固定） | 400~1200 步长 50，共 17 档 | 闭式 → 取第一档可行解 |
| 每层等级 | 候选等级数（默认 3） | 各算一次"该层柱造价"，取最小 |
| 各层之间 | — | 无约束耦合，**各自独立** |

注意：这一层是**真穷举**（候选少且有序），不是启发式。

## 耦合有多大：用数据说话

变量会通过**刚度重分布**互相影响。在 10 层案例上对比"基线（全 700）"与"优化后"的实际轴力：

| 分组 | 轴力变化 |
|---|---|
| 中柱 | +1.4% ~ +1.7% |
| 边柱 | -10% ~ -11.6% |
| 角柱 | -19% ~ -23% |

耦合**不能忽略**（最大 23%），但方向单一：边/角柱的下降主要来自**柱自重本身变小**
（700×700 → 400×400，每层自重 44 kN → 14 kN）。

## 收敛判据：不动点

因为有力重分布，选型后必须把**新轴力代回去再选一次**：

```
opt --res <新工程> --compare <上一版 sections.json>
  → 输出"无改动" = 不动点，收敛
  → 有改动则再走一轮
```

10 层案例在第 2 轮就达到不动点；且**解析预估造价 191,804 元 与 实算 191,804 元 完全一致**
——说明"用控制柱的配筋代表整组"这个近似在该模型下是自洽的。

## 约束的处理方式

| 约束 | 是否进选型 | 说明 |
|---|---|---|
| 轴压比 Uc ≤ 限值 | 进 | 唯一进选型的约束；取 `轴压比目标` 留余量（默认限值的 96%） |
| 柱截面边长 ≥ 最小边长 | 进 | 默认 400mm（GB50011 6.3.5，抗震二级且超过 2 层） |
| 纵筋率、箍筋率限值 | 否 | 由 YJK 选筋保证，实算复核 |
| 层间位移角、刚度比等**全局**约束 | 否 | **不可逆、无法逐柱分解**，只能实算复核 |

因此"最优"的成立前提是：**被忽略的约束恰好都不控制**。
本案例实算结果：全楼 0 超限、最大层间位移角 1/1951（限 1/550）——余量很大，前提成立。
若位移角接近限值，就必须把它纳入迭代（见"可扩展方向"）。

## 造价口径（重要）

默认 `口径 = 只算柱`：

```
混凝土 = 全截面面积 × 柱段长 × 单价(按该柱所在层的等级)
模板   = 柱周长 × 柱段长 × 单价
纵筋   = 各组合中四边计算配筋之和的最大值(不低于构造最小配筋率) × 柱段长 × 7850 kg/m³
箍筋   = 体积配箍率 Rsv × 核心区面积 × 柱段长 × 7850 kg/m³
```

**注意**：混凝土等级是每层统一的，实际也作用到该层的梁与板（梁板混凝土量常远大于柱）。
只算柱会**放大提高等级的收益**。评审时若需"柱+梁+板"口径，要另行统计——本技能不提供。

另一个容易踩的点：`wpj` 里的 `Rs`（全截面配筋率）是**构造值**，不同截面都恒等于同一个数
（一个常见小值），**不能**当纵筋用量；必须用四边计算配筋之和。用错会让纵筋量偏小一半以上。

## 边界（无全局最优保证的自由度）

1. 柱型固定为矩形混凝土柱——圆柱、型钢混凝土、钢管混凝土、叠合柱都没试
2. 梁、板截面与配筋固定
3. 柱网、跨度、层高、荷载、抗震参数固定
4. 不含施工代价（变截面/变等级的模板与人工增量）
5. 等级"层内统一"是外部约束；若允许层内分组不同等级，还能再省一点
6. 位移角等全局约束只做事后核验

## 可扩展方向

| 方向 | 做法 |
|---|---|
| 纳入全局约束（位移角/刚度比） | 用响应面或灵敏度迭代：位移角超限时按下部楼层刚度加权加大截面，再实算复核 |
| 改"柱+梁+板"造价口径 | 在 `cost.py` 增加梁、板工程量统计（按几何算，不依赖 wpj） |
| 放开层内等级统一 | 把"每层等级"变量细化到"每层×每分组"，`section_opt.optimize` 里去掉层内合并即可 |
| 纳入柱型比选 | 把本技能作为"单柱型内的造价优选"内核，外层套 `column-scheme-comparison` |

## 什么时候该引入大模型逐轮参与

本问题是"约束局部可逆 + 迭代便宜"，**不适合**让大模型逐轮拍板——脚本更快、更准、更可复现。
大模型真正值钱的位置是：

1. **诊断归因**：例如认出 `wmass.out` 里的 `C0` 是"标准层参数没设"，而不是"柱子不够"
2. **需求→约束翻译**：把"业主不接受每层变截面"这类软约束变成变量限制
3. **昂贵迭代下的候选生成**：每轮几十分钟时，用少量"有理由的"试验替代网格搜索

无论哪种，LLM 的产出都应落到**可检查的结构化产物**（配置/脚本改动），而不是直接给数字。
