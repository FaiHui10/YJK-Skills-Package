# Excel 报告规格（交付物）

报告的读者是**结构工程师和造价/甲方**，他们不会看脚本日志。
所以报告必须做到：**结论可追溯、口径无歧义、不可核实的地方明说**。

---

## 一、页签结构

报告为 6 个页签（页数可按工程调整）：

| 页签 | 作用 | 必填内容 |
|---|---|---|
| `1-说明` | 口径与结论 | 工程概况、方法、判据与限值、**范围声明**、结论 |
| `2-现状与优化对照` | 逐（标准层 × 柱位组）对比 | 原截面 → 优化截面、截面面积变化率、等级 |
| `3-工程量对比` | 省钱在哪 | 混凝土体积、模板面积、纵筋/箍筋重量、合计与降幅 |
| `4-逐柱明细` | 便于抽查 | 逐（自然层 × 柱号）的截面、材料、Uc、超限标记 |
| `5-复核清单` | 判据逐条勾选 | 每条判据的实算值、限值、是否满足、**复核人/日期** |
| `6-实算复核` | 实算证据 | 见下 |

> `1-说明`、`5-复核清单`、`6-实算复核` **必须有**。

### `1-说明` 必写的两块

**（a）范围声明** —— 明确说清哪些数据能核实、哪些不能。示例：

> 本报告的"原设计截面"取自模型库 `tblColSect` 中引用数=0 的遗留行，
> 与原始设计模型可能不一致；
> 因此第 2、3 页的**工程量对比仅供趋势参考，不能作为结算依据**。
> 可核实的是第 5、6 页的**实算复核结果**——它们来自本次导入后的真实计算输出。

**（b）口径变更说明** —— 若报告的口径或某项结论与上一版不同，
写明"原口径…，现口径…，变更依据…"，不要静默改口径。示例：

> 原说明称"逐层混凝土等级存于 `.yjk` 文件、脚本读写不到"。
> 现口径：等级的有效字段是 `tblStdFlr.Para` 下标 2/4/5/6，写库即生效。
> 依据见第 6 页的实算复核（`Rcc=` 与 `Uc` 同步变化）。

### `6-实算复核` 必含的五张表

| 表 | 内容 |
|---|---|
| A | **工况对照**：原工程 / 基准 / 各迭代轮的"轴压比超限行 / 配筋率超限行 / 合计" |
| B | **逐组轴压比**：每（标准层 × 柱位组）的截面、砼等级、控制柱号、控制自然层、Uc、限值、判定 |
| C | **其他控制指标**：位移角（X/Y）、刚度比（Ratx1/Raty1/Ratx2/Raty2）、最大配筋率超限条数 |
| D | **采用截面**：本轮实际写入模型的截面清单（与 `sections.json` 一致） |
| E | **关键排查记录**：哪些异常是既有的、哪些是本次引入的、依据是什么 |

## 二、写报告的硬规矩

1. **改表前先备份**
   `<报告名>_备份_YYYYMMDD.xlsx`，并在 `1-说明` 里注明备份文件名。
2. **不许把不可核实的数据当结论**。工程量的"原值"若来源可疑，
   就在旁边标注来源与可信度，不要只给一个降幅百分比。
3. **超限项要单独列，并说明归因**。示例写法：
   > 残余 N 个柱段最大配筋率超限（A%~B% vs 限值 C%），全部集中在角柱（某组/某柱号）。
   > 该现象在**原模型**与**未改动基线**上同样存在，**属既有问题，非本次优化引入**；
   > 需单独加大该柱或调整配筋。
4. **对比要用同一口径**。例如"与基线逐位一致"这种话，只有在真逐位比过之后才能写
   （如刚度比优化前后逐位比对 —— 一致则属既有问题，不是优化造成）。
5. **每轮迭代单独一行**，不要把不同轮次混成一个数字。对照表模板：

   | 方案 | 轴压比超限行 | 配筋率超限行 | 结论 |
   |---|---|---|---|
   | 原工程 | ? | ? | 作为基线；先确认等级写对，否则出现假性超限 |
   | 基准截面 + 真等级 | 应为 0 | ? | 等级写对后轴压比应全过 |
   | 迭代 1（各组均折减） | ? | ? | 若有某组 Uc 超限，把它排除在折减外 |
   | 迭代 N（最终） | **0** | ? | **推荐**；给出最不利 Uc 与限值 |

6. **报告里的数字必须能追到脚本输出**。第 5、6 页的关键数字应来自
   `verify_results.py --json` 的结果文件，并在文件名/日期上注明。

## 三、`report.py` 的用法

```powershell
& $py -X utf8 -B "<脚本>\report.py" --config config.json --out 汇报.xlsx iter_*.json
```

- 传入多轮 `iter_*.json`（`colopt.py iterate` 的产物）会自动生成对比表。
- 生成的是**新工作簿**。若要**更新已有的工作簿**（例如只在其中几页追加内容），
  用 openpyxl 直接改，**并先备份**：

```python
import shutil, openpyxl
shutil.copy2(路径, 路径.replace(".xlsx", "_备份_%s.xlsx" % 日期))
wb = openpyxl.load_workbook(路径)
# 改单元格 / 新建页签 …
wb.save(路径)
```

- 中文字体与列宽要显式设，否则在别人机器上会挤成一团：

```python
from openpyxl.styles import Alignment, Font, PatternFill
ws.column_dimensions["A"].width = 18
ws["A1"].font = Font(bold=True)
ws["A1"].alignment = Alignment(horizontal="center", vertical="center", wrap_text=True)
```

- 交付前把工作簿交给用户查看。**不要写死某个平台的文件推送工具名**
  （如 `present_files`）—— 换到别的 agent/IDE 上那个工具并不存在。
  用中性的说法，让调用方按自己环境的能力去交付：
  "把生成的 `<报告名>.xlsx` 路径回报给用户，并提示可直接打开查看"。
