# 筏板布桩优化（YJK 基础 / JCCAD）

在给定桩数、桩径与单桩承载力不变的前提下，重新排布板下桩位：高反力区压到最小桩距，低反力区拉大间距或删桩，再用 YJK 实算复核。

## 前置条件

- 工程目录含 `Jccad_0.ydb`（基础模型库，`app_Pile` 表即桩位）与 `基础计算及结果输出\YJK-F桩承载力验算.out`（基准反力）
- 已装 `yjk-auto-drive` 技能（本技能靠它计算），解释器用 `%USERPROFILE%\.yjk-auto\venv\Scripts\python.exe`
- **改桩位前必须关掉打开该工程的 YJK**（见「陷阱」第 1 条）

## 数据要点

| 项 | 位置 | 说明 |
|---|---|---|
| 板下桩 | `app_Pile where DaisFlag=-1` | 其余为承台桩，不要动 |
| 桩定义 | `DEF_Pile` | `B`=桩径，`F1`=单桩承载力特征值 Ra |
| 桩顶标高 | `app_Pile.z` | 沿用最近原桩，勿统一填 0 |
| 反力 | `YJK-F桩承载力验算.out` | 按 `ZH-n` 分块，行次 `组合号  Nk  Ra` |
| 桩号对应 | `.out` 的 `ZH-n` ↔ `app_Pile order by ID` | 按 ID 排序一一对应 |

判定（非地震组合）：单桩 `Nk,max ≤ 1.2Ra`；群桩平均 `Nk,avg ≤ Ra`。地震组合为 `1.5Ra` 与 `1.25Ra`。

## 标准作业（一条命令）

```powershell
& $PY -X utf8 "$S\run_layout.py" --dir "G:\...\T1h700b-BP" --layout "N54\layout.csv" --root "<YJK安装目录>"
```

按 `kill YJK → 移出恢复源 → 写入布局 → YJK 重算 → 核验` 五步串行执行，任一步失败即停。
只想改模型不重算，加 `--skip-calc`（注意：写入会清掉旧结果，之后仍需补跑计算）。
`--ra` 缺省取 `DEF_Pile` 的最大 `F1`；`--min` 缺省 2500 mm。

## 流程（细节）

0. **前置清理（每次改桩都要做，这是全流程可靠的前提）**：
   先 `yjk_auto.py kill`，再 `scripts/prep_model.py --dir <工程目录>`。它把 YJK 会用来恢复旧模型的文件移出工程目录（默认移到 `<工程目录上级>\_备份移出\<工程名>-<时间>\`）：
   `基础备份\`、`<工程名>_F.yjc/.tmp/.yg/.ygt/.ygjcbak`、`Jccad_0_ydb.dat`。
   **已验证**：不做这一步，基础模块保存时会把 `app_Pile` 写回旧桩（实测 56 桩、z 全 0）；做了这一步，重新打开工程后界面显示与 ydb 一致。
1. **读基准**：`scripts/bp_grid.py <工程目录>` 打印逐桩最大 Nk 网格、行列平均、超限根数。据此判断反力分布形态（常见为南侧/东侧偏高、板边悬挑越大边桩反力越高）。
2. **定桩数下限**：`N ≥ ceil(总反力 / Ra)`。峰值约束通常更紧；实际可行为该式下限 + 2~3 根。
3. **生成候选布局**，三种做法按效果排序：
   - **规则变距**（最稳，推荐）：用 `scripts/bp_gridgen.py` 给 x 列距、y 行距与四边边距，边距要小（0.9~1.0 m）以免边桩悬挑过大；高反力侧压到接近最小桩距。
   - **删冷桩**：在规则网格上删掉实测反力最低的 2~4 根（多位于中部低荷载区），可直接减桩数而不抬高峰值。
   - **等荷载分带**（`scripts/bp_optim.py`）：按从属荷载把筏板分成等荷载条带再细分。**实测常劣于规则变距**——它忽略板边悬挑效应，容易把桩拉到远离板边处导致峰值反而升高。仅作探索。
4. **写回模型**：`scripts/apply_layout.py <工程目录> <layout.csv>`（`layout.csv` 表头 `x,y,z`，单位 mm）。它按模板行复制其余字段、删旧板下桩、写新桩并清理旧结果。
5. **实算**：`jc.py --dir <工程目录> --root <YJK 8.x 安装目录> --output`（见 yjk-auto-drive）。
6. **复核**：`scripts/check_layout.py --dir <工程目录> --layout <layout.csv>`，一次输出桩数、桩顶标高分布、最小桩距、与 CSV 一致性、峰值/最小 Nk、超限根数、群桩平均与判定。

## 脚本

```powershell
$PY = "$env:USERPROFILE\.yjk-auto\venv\Scripts\python.exe"
$S  = "<skills>\pile-layout-opt\scripts"

& $PY -X utf8 "$S\bp_grid.py"    "G:\...\T1h700b-BP"
& $PY -X utf8 "$S\bp_gridgen.py" --prj "G:\...\T1h700b-BP" --work "G:\...\_work" --tag L5 --xg 3.45,3.35,3.35,3.20,3.00,2.80,2.70 --yg 3.15,3.10,3.00,2.90,2.75,2.60 --mgw 0.95 --mgs 0.95 --mge 0.95 --mgn 0.95
& $PY -X utf8 "$S\bp_optim.py"   --src "G:\...\T1h700b-BP" --n 54 --cols 8 --tag N54 --min 2500 --edge 900
& $PY -X utf8 "$S\bp_dens.py"    "G:\...\T1h700b-BP"                      # 从结果导出强度场 x,y,dens
& $PY -X utf8 "$S\run_layout.py" --dir "G:\...\T1h700b-BP" --layout "N54\layout.csv" --root "<YJK安装目录>"   # 五步全自动
& $PY -X utf8 "$S\prep_model.py"  --dir "G:\...\T1h700b-BP"            # 改桩前必跑，移出恢复源
& $PY -X utf8 "$S\apply_layout.py" "G:\...\T1h700b-BP" "N54\layout.csv"
& $PY -X utf8 "$S\check_layout.py" --dir "G:\...\T1h700b-BP" --layout "N54\layout.csv"
```

`bp_gridgen.py` 的 `--xg/--yg` 是相邻间距（m），列数 = 间距数 + 1；`--mgw/--mgs/--mge/--mgn` 是西/南/东/北边距。

## 陷阱

1. **YJK 开着时写 ydb 会被内存副本覆盖**。必须先 `yjk_auto.py kill`，或确认无 `yjks.exe`。
2. **YJK 会用自己的备份/图形数据把旧桩恢复回来（本技能最坑的一条）**：`基础备份\`、`<工程名>_F.yjc/.tmp/.yg/.ygt/.ygjcbak`、`Jccad_0_ydb.dat` 都是基础模块的模型与恢复源。
   只改 `app_Pile` 不够——用户一进基础模块并保存，`app_Pile` 就被写回旧桩，**且 `z` 被写成 0**（实测会出现桩数被写回旧值、z 被写成 0）。
   可靠做法：`scripts\prep_model.py --dir <工程目录>` 把这些文件整体移出工程（不要只改名留在原地），再写入新桩、重算。按此处理后，界面显示与 ydb 一致。
3. **改完最好让 GUI 再保存一次**：GUI 保存会把 `z` 统一重算（实测 z 会被统一重算），如需保留原桩顶标高，保存后立即 `check_layout.py` 复核 `z 分布` 并重算。
4. **结果缓存必须全清，只删 `.out` 不够**：`基础计算及结果输出\` 里的 `jccad.result`、`jccad.ydb`、`Jccad_1.ydb`、`jccad.pre`、`element.data`、`中间数据\` 都会让 YJK 复用**上一版模型的网格与反力**。
   实测：126 桩改 116 桩时只删 `.out`，重算出的峰值 4743（假超限）；把这 6 项一起清掉后同一布局为 3044，判定通过。`apply_layout.py` 现已代做。
5. **GenData 会重写 ydb**：`jc.py --gen-only` 结束时会重写 `Jccad_0.ydb`，桩数应保持不变——若变了，说明有陷阱 2 的文件在起作用。
6. **边距是控制峰值的第一杠杆**：边桩从属面积小但悬挑大，边距从 1.8 m 收到 0.95 m 可使峰值降 5~10%。边距已到工程下限后，峰值只能靠减桩数让步。
7. **z 不能统一给 0**：`z` 是桩顶标高，应沿用原桩（本项目为 −13700 / −10000）。
8. `.out` 解析必须按 `ZH-n` 分块并在章节标题（`一、`/`二、`/…）处截断，否则后续表的数字会串进来，峰值判错。
9. **组合前缀的含义别弄反**：`W( k)` 与无前缀 `( k )` 都是**非地震**（限 1.2Ra、群桩平均限 Ra），`E( k)` 才是**地震**（限 1.5Ra、平均限 1.25Ra）。按"有前缀=地震"判会把 20 个非地震组合误判成地震，峰值结论完全反。`check_layout.py` 已按此分类。

## 已验证结论（T1h700b-BP 实例）

- 原 56 桩等距 3.1 m：峰值 11035（96.8%×1.2Ra）
- 变距 + 删 2 根冷桩 → **54 桩**：峰值 10620（93.2%），群桩平均最大 9002（94.8%），最小桩距 2600 ≥ 2500
- 53 桩：峰值 10795、平均 9080（95.6%）；52 桩群桩平均将超 98% → 不可行
- 需要更大余量时可回退 56 桩变距（峰值 10401/91.2%、平均 8680/91.4%）

## 抗浮桩布置优化（1.0 恒 + 1.0 高水位）

适用：平筏板 + 抗拔桩，承台桩不动，只调板下桩（D500，F2=400），控制**组合 51（1.0 恒 + 1.0 高水）**不超 F2，
任意两桩中心距 ≥ 1750 mm。完整实录（含数据台账、闸门、逐轮数字）见 `references/anti-floating-f2.md`。

### 判定与刚度

| 项 | 取法 |
|---|---|
| 反力 | `基础计算及结果输出\jccad.ydb` → `tblPileNL`，`CombType=1, CombID=51`；`N` blob 第 1 个 float |
| 判定 | D500 `N ≥ -400`；D1200 `N ≥ -2200` |
| 桩刚度 | 抗拔刚度 = F2/0.01 = **100×F2**（D500 40,000、D1200 220,000 kN/m），在 GUI 的「桩刚度」命令按桩定义设 |
| 桩刚度取不到时 | 退用全局 `CalPara.fPILEK`（取多数桩的 D500 值；D1200 偏柔→对 D500 偏安全） |

> 直接改 `app_Pile.fKn/fALFQ/fKm` 或 `NIK` **无效**（实测重算后一个数不变），只有 GUI 里点过「桩刚度」的状态才生效。

### 前置：先过一致性闸门

```powershell
& $PY -X utf8 "$S\af_gate.py" --dir "<工程目录>" --caps 208 --combos 52 --dead-load 1164014
# 5 项全 PASS 才继续；FAIL 说明模型/结果不是同一版（见 yjk-auto-drive 的 foundation 文档）
```

### 可复现工作流（移 → 补 → 抽 → 补）

荷载一变（尤其上部改成"墙下线荷载"），旧布置会**又缺桩又闲桩**（本项目一晚从 0 超限变成 807 根超限 + 309 根闲桩）。
所以顺序是**先搬闲桩（不涨桩数）→ 补峰值 → 抽稀 → 再补峰值**；一上来就抽稀或全局加桩都浪费。

1. **基准**：`af_gate.py` 通过后读逐桩：超限数、最大上拔、`|N|` 分档，并按 8×8 板块看各格均值。
   同时做反力口径校验：`ΣN(51) ≈ Dead − 高水浮力`（本项目 −324,814；对不上就是组合号/水位取错）。
2. **移**：把 `|N| < 200` 的板下桩当池子，逐个搬到峰值附近 1.75~4.2 m 的空位
   （新位 ≥1750 距**结果库全部桩**、距板边 ≥300、在筏板内）；每个峰值搬 `ceil((|N|-370)/130)+1` 根。
   实测：807 根超限时搬 58 根 + 补 300 → 超限 443。
3. **补**：池子挪完或附近无空位时直接补桩（同公式）。
4. **抽（贪心集合覆盖，推荐）**：`af_greedy.py` 逐个评估"删这根会不会把 6 m 内邻居顶超"，
   只删"邻居接得住"的、且每次删当前拔力最小的那根；预测邻居 ≤ `--target` 才动手。
   比"按 |N| 排序删"稳得多（后者删完必冒新峰）：本项目 1,616→1,456 根，超限 6→7 基本不变。
   也可用老的阈值法（4 m 内无 `|N|>320` 时删 `|N|<250~280`）。
5. **再补**：只在新增超限点补回来。收敛判据：0 根（或 1~2 根 ≤1.05F2）。

每步都是完整 YJK 实算（3~7 min/轮，**每轮重开会话**）；批量迭代用 `af_iterate.py`：

```powershell
& $PY -X utf8 "$S\af_iterate.py" --dir "<工程目录>" --f2 "1:400,0:2200" --combo 1-51 `
      --prune-below 260 --spacing 1750 --edge 300 --rounds 2 --root "<YJK 8.x 安装目录>"
```

### 本项目实测轨迹

| 阶段 | 板下桩 | 总桩数 | 超 F2 | D500 最大 | 说明 |
|---|---|---|---|---|---|
| 旧布置 + 新荷载 | 1,323 | 2,229 | **807** | −718.1 | 线荷载把上拔压到墙下，布置不匹配 |
| 移 58 + 补 300 | 1,623 | 2,529 | 443 | −557.6 | 先搬后补 |
| 移 83 + 补 300 | 1,923 | 2,829 | 2 | −407.6 | 数量偏富余（均值 −273） |
| 抽 350 + 补 141 | 1,714 | 2,620 | 1 | −406.3 | 均值 −299 |
| 抽 289 + 补 150 | **1,575** | **2,481** | **1** | **−404.2** | 均值 −315，`|N|<200` 归零 |
| 贪心 R1（target 380） | 1,529 | 2,435 | 6 | −416.6 | 删 87 根，均值 −344 |
| 贪心 R2（target 392） | 1,473 | 2,379 | 7 | −417.5 | 删 56 根，均值 −353 |
| 贪心 R3（target 396）+补 1 | **1,456** | **2,362** | **7** | **−417.4** | 均值 −356，利用率 89% |

分布形态（2,481 桩、组合 51）：均值 323、中位 323、P95 368、最大 404.2；300~340 占 56.7%；
按 8×8 分板块，64 格均值全部落在 **−284~−369**，没有低效板块。

**经验**：净上拔只有 32 万 kN 却 807 根超限 → 不是总量不足，是"桩站错位置"；
`移` 能把超限砍近一半而桩数不变，`抽` 必须配 `再补`（抽 289 根冒 152 根，补 150 收口，净减 139）。

### 脚本

| 脚本 | 用途 |
|---|---|
| `af_gate.py` | 5 项一致性闸门（不启动 YJK，秒级） |
| `af_relayout.py` | **移闲桩 + 补峰值**（荷载变了、旧布置又缺又闲时先跑这个） |
| `af_greedy.py` | **贪心集合覆盖抽稀**（邻居接得住才删，比按 \(|N|\) 排序稳） |
| `af_iterate.py` | 抽稀 + 补峰值 多轮迭代（每轮闸门） |
| `af_prune.py` / `check_layout.py` | 单独做抽稀 / 复核桩距与标高的场合 |
| `apply_layout.py` / `prep_model.py` | 写回布局 / 改桩前移走 GUI 恢复源 |

### 陷阱

1. **结果串版**：不导入就点「生成数据」会用 GUI 里的旧模型；导入后不覆盖回 `Jccad_0.ydb` 会丢组合/荷载。两头都要做，并每轮过闸门。
2. **桩距检查要用结果库**：`app_Pile` 里只有显式桩，模板生成的承台桩不在里面；按 `app_Pile` 判 1750 会让新桩撞桩并被静默丢弃。
3. **会话内改 ydb 无效**：每轮重新开 YJK。
4. **旧结果必须全清**：`jccad.result` / `jccad.ydb` / `Jccad_1.ydb` / `jccad.pre` / `element.data` / `中间数据\` / `*.out`。
5. **别用 YJK 的 1.8D 报警代替 1750 审计**（D500 的 1.8D 只有 900 mm）。
